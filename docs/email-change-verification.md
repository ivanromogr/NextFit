# Cambio de correo verificado

`PUT /api/auth/email` valida JWT, contraseña y unicidad, pero no cambia el correo: crea un token aleatorio de 256 bits, persistiendo sólo SHA-256, y envía la confirmación al nuevo email. Una solicitud posterior consume las pendientes anteriores. `POST /api/auth/email/confirm` consume el token, vuelve a comprobar unicidad y cuenta activa, cambia el correo y revoca sesiones y resets pendientes; si el email fue ocupado entre ambos pasos, no modifica la cuenta. El token es de un uso y expira según `APP_AUTH_EMAIL_CHANGE_TTL_MINUTES` (30 por defecto). Cleanup conserva tokens válidos y retira expirados o consumidos tras `APP_CLEANUP_EMAIL_CHANGE_RETENTION_DAYS` (7 por defecto). La URL se configura con `APP_EMAIL_CHANGE_CONFIRM_URL`; web usa una URL estable y móvil admite `nextfit://confirm-email-change?token=...`. Ningún cliente persiste el token.
